## 一、视觉系统（科技风 · 带指纹）

### 1.1 设计立场

科技风不等于"近黑底 + 标准青发光"的通用赛博模板（AI 生成页头号俗套）。
本方案做**有指纹的科技风**，三处专属印记：

1. **底色带蓝绿而非纯黑**——深空青 `#081420`，面板 `#0E1F2E`，从产品名 Loop
   （回路）来的"电路板走线"纹理替代通用网格；
2. **主光色用镜青 `#56D8E8`**（我们 v1 的 token 延续），非标准 cyan；
3. **动效只花在三处、每处有职责**：hero 架构图流光（讲工作流）、决策树生长/点亮
  （讲因果）、实况事件驱动（讲"正在发生"）。无满屏 fade-slide。

### 1.2 设计令牌

| 令牌 | 值 | 用途 |
|---|---|---|
| 深空 Deep | `#081420` | 页面底色 |
| 面板 Panel | `#0E1F2E` / `#12283A` | 卡片/树底 |
| 走线 Trace | `#1E3A50` | 边线、回路纹理 |
| 镜青 Lens | `#56D8E8` | 主光色：流光、激活节点、链接 |
| 信号红 Risk | `#FF5C5C` | STRONG / 风险确认 / 印记语义 |
| 信号黄 Warn | `#FFB454` | PARTIAL / 中风险 |
| 信号绿 Safe | `#3ED598` | NONE(抵御) / 低风险 / 在线状态 |
| 紫外 Live | `#8B7CF6` | 专用于"实况运行中"状态流 |
| 字体 | 黑体 UI + 大数字用细黑大字（重字重对比做层级） | 中文显示字用 Light 大字号，规避"处处加粗" |

`prefers-reduced-motion`：流光与树生长退化为静态高亮。

## 三、Tab 0 总览

### 3.1 Hero（保留现有架构图流光，重新上色至新令牌）

4.2s 接力时序不变（0 / .45×3 / .9 / 1.5 / 2.2），节点随光到达脉冲。

### 3.2 系统路由树（新增，hero 下方）

**数据**（全部现成）：observability 映射（70/30 冻结）+ 反馈参与模式 + 独立评审隔离。

```
                安全任务池
               ┌──┴──────────────┐
        内容可观测域 70%        目标合规域 30%
          （虚假信息/入侵/隐私…）  （冒充专家/经济损害/政务…）
               │                  │
          内容裁判 🔍            目标推进裁判 🔍
               │                  │
        观察记录（默认）      观察记录（默认）
        引导反馈（实验）      引导反馈（实验）
               └──┬──────────────┘
              完整测试轨迹
                  │
          独立评审官 ⚖️（离线，闭环外）
```

**静态态**：两条路由分支常亮，标注各域风险类别中文清单；"观察/引导"双模式用
图例说明（呼应研究发现：可观察 ≠ 该干预）。

**实况联动**（对应决策 ③）：
- 任务加载 → 所属域分支高亮加粗，另一域降暗；
- 裁判调用 → 对应裁判节点脉冲 + 镜青描边；
- 控制器动作 → "引导反馈"节点瞬时点亮（观察模式下不亮——本身就是机制展示）；
- 独立评审启动 → 评审官节点亮紫外（离线阶段色）。

### 3.3 一键体检表单（沿用 v1 交互，皮肤更换）

检测对象（本地/API 黑盒+测试连接）、检测方式三选、开始/示例报告按钮、专家模式
开关（默认关 = 友好术语）。

## 四、Tab 1 实况演示（核心战场）

### 4.1 实况引擎

**复用服务器侧 `run_live_session.py`**（4090 真模型、事件流 schema 已验证：
session_started / loading / round_started / role_working / red_message /
judge_message / control_message / session_complete），GUI 作为事件消费者，
不重写推理层。本地演示降级为回放模式。

### 4.2 三栏布局

```
┌─────────────┬──────────────────────────┬─────────────┐
│ 智能体状态坞  │  对话气泡流（微信风格）      │ 实况决策树    │
│ 主智能体 ●   │  🧑‍🔬 测试员：…            │  ○第1轮      │
│ 红队测试员 ●  │  🤖 模型：…              │   │REFINE    │
│ 内容/目标裁判○│  ⚖️ 判决：目标推进 PARTIAL │  ●第2轮      │
│ 独立评审官 ○  │                          │   │KEEP     │
│ (状态随事件)  │  (友好术语，专家键切英文)   │  ○第3轮…    │
└─────────────┴──────────────────────────┴─────────────┘
```

### 4.3 实况决策树点亮规则（决策 ③ 的落地）

| 事件 | 树的反应 |
|---|---|
| session_started | 根节点出现（任务名+域路由色），系统树对应分支点亮 |
| red_message | 当前轮节点出现，边框镜青脉冲，节点内显示策略中文名 |
| 目标响应到达 | 节点半亮（等待判定） |
| judge_message | 节点填充信号色（红 STRONG/黄 PARTIAL/绿 NONE），标签写判定结论 |
| control_message | 出边生长 + 决策标签（保持/细化/换策略/回正），下一节点预备 |
| session_complete | 全路径流光扫过一遍 → 裁决徽章（风险确认🔴/抵御成功🟢） |

视觉上"树在长"即演示本身：评委看到的不是静态图，而是系统逐轮做决策的过程。
